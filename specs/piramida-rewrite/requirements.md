# Requirements: Пирамида 74 — переписывание сайта

## Summary

Сейчас сайт бильярдного клуба «Пирамида» в Челябинске — это PHP-одностраничник на jQuery. Цены, меню и акции зашиты в разметку или в JPG-картинки. Единственная таблица БД (`plan`, календарь турниров) потеряна после атаки на хостинг Beget. Владелец не может сам менять даты турниров, афиши, цены аренды и меню. Около 70% CSS и JS сайта не используется. В коде лежат секреты.

Решение: переписать сайт на Next.js 16 со стартера этого репозитория, сохранив внешний вид, но сделав нормальную адаптивность. Добавляются:
- админка для 1–2 администраторов: турниры, цены, меню, сеты, акции, галереи, заявки, блог, настройки;
- калькулятор стоимости заказа на N гостей: аренда столов, позиции меню, банкетные сеты, отправка расчёта в клуб;
- блог по образцу проекта billiard-darom.

Первичные данные берутся из распознанных прайсов (`data/res-transcription.md`) и цен старого сайта (`data/legacy-notes.md`).

Результат: быстрый, SEO-оптимизированный сайт на собственном VDS с Dokploy, контент которого владелец полностью ведёт через админку.

## Goals

- Визуально повторить старый сайт на ширинах 1920 и 320, с адаптивом через `clamp()`, max-width и брейкпоинты. Только светлая тема.
- Хранить в БД и редактировать через админку: турниры (даты, афиши), тарифы аренды, меню, банкетные сеты, акции, галереи, тексты и контакты, статьи блога.
- Сделать калькулятор с сохранением состояния в URL. Сервер пересчитывает сумму при отправке заявки.
- Сохранять заявки в БД и отправлять уведомления на email (российский SMTP) и в Telegram (без ПДн по умолчанию).
- Перенести блог из billiard-darom с исправлением найденных уязвимостей. Добавить отложенную публикацию, RSS, авторов и медиатеку.
- Соблюсти 152-ФЗ: отдельный документ согласия, неотмеченный чекбокс, версии документов, Метрика только после согласия, срок хранения заявок.
- Деплоить через Docker на Dokploy. `next build` должен проходить без БД, миграции выполняются при старте контейнера, нужны healthcheck и бэкапы.
- Mobile Lighthouse Performance ≥ 90, LCP < 2.5 с.

## Non-Goals

- Поддержка нескольких городов (сайт 72, Тюмень). Поле `branch_id` не закладываем.
- Онлайн-бронирование конкретных слотов и столов с проверкой занятости. Достаточно заявки с желаемым временем.
- Онлайн-оплата.
- Тёмная тема.
- Личные кабинеты клиентов и регистрация пользователей.
- Многоуровневые роли в админке: одна роль `admin`.
- Автоматическое применение скидок по акциям в калькуляторе: только подсказка.
- AI-функции стартера: чат, OpenRouter.
- CSV-импорт турниров: вместо него кнопка «Дублировать».

## Acceptance Criteria

- [ ] Главная повторяет старый сайт по составу и порядку секций, токенам и эффектам. Добавлены блоки «Калькулятор» и «Из блога».
- [ ] Ближайшие 5 турниров отбираются по условию `end_date >= сегодня` (Екатеринбург), даты выводятся по-русски: «5 марта», «5–7 марта», «30 марта – 2 апреля».
- [ ] Изменения в админке сразу видны на сайте (`updateTag`).
- [ ] `/menu` показывает всё меню из БД, включая варианты объёмов и общие сетки цен.
- [ ] Калькулятор корректно считает переход через полночь, ночь пт→сб по тарифу пятницы, смену тарифа посреди брони, получасовые интервалы, VIP-комнату, флаг пенсионера и «дыры» в тарифах. Ссылка с параметрами воспроизводит расчёт.
- [ ] Отправленная заявка сохраняется в `leads` с номером, пересчитанным на сервере снимком расчёта и версией согласия. Email и Telegram уходят, ошибка уведомления не теряет заявку.
- [ ] `/admin` недоступен без входа. Каждый Server Action проверяет роль. Регистрации нет. Первый админ создаётся скриптом.
- [ ] Блог: черновики, отложенная публикация, рубрики, теги, авторы, оглавление, RSS, OG-изображения, 301 при смене slug.
- [ ] Загрузки: только jpeg/png/webp/avif до 10 МБ, генерация вариантов sharp, отдача из volume с immutable-кэшем, защита от path traversal.
- [ ] `docker build` проходит без БД. Контейнер применяет миграции при старте, `/api/health` отвечает 200.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm build:ci`, `pnpm test` и Playwright e2e проходят.

## Assumptions

- Цены аренды берутся из `<section id="price">` старого сайта, а не из JPG. Ночной тариф почасовой (3500 и 4800 ₽/ч). Подлежит подтверждению клубом, админ сможет поправить.
- Операционные сутки — с 09:00 до 09:00 следующего дня. Время с 00:00 до 08:59 относится к предыдущей дате визита.
- В общем зале 4 места на стол по умолчанию. Число столов уточнит клуб, в seed — 12.
- VIP-комнат три (VIP 1, 2, 3). В seed у всех цена 1400 ₽/ч днём и 4800 ₽/ч ночью, админ поправит. Цена считается за комнату.
- Telegram-чат общий с Тюменью, поэтому в сообщение добавляется «Город: Челябинск». Токен бота будет перевыпущен.
- VDS физически находится в РФ.
- Банкетные сеты создаёт админ. В seed — 2 примера.

## Technical Constraints

- Next.js 16 (последний 16.x), `cacheComponents: true`, `output: 'standalone'`, React 19.2, Tailwind v4 (CSS-first `@theme`), shadcn/ui (new-york), lucide-react.
- Drizzle ORM + драйвер `postgres`, Postgres 18. У всех не-BetterAuth таблиц UUID PK с `defaultRandom()`. После изменения схемы выполнять `pnpm db:generate` и `pnpm db:migrate`. **`drizzle-kit push` запрещён.**
- Better Auth 1.6, плагины `admin` и `twoFactor`, `disableSignUp`, rate limit в БД. IP клиента берётся из `x-real-ip`.
- Кэш:
  - чтение данных — через `'use cache'` + `cacheTag`, внутри `<Suspense>` после `await connection()`;
  - «сегодня» передаётся аргументом;
  - `generateStaticParams` не используется для страниц, зависящих от БД;
  - в Server Actions вызывается `updateTag`, в route handlers — `revalidateTag(tag, 'max')`.
- Одна реплика приложения (in-memory кэш).
- Часовой пояс — `Asia/Yekaterinburg`. Все цены хранятся целыми числами в рублях.
- Файлы лежат в `UPLOAD_DIR=/data/uploads` (Docker volume) и отдаются через `/media/[...path]`. SVG запрещён.
- Формы админки: react-hook-form + zod 4 + Server Actions. Каждый action: `requireAdmin()` → zod → транзакция → `audit_log` → `updateTag`.
- Новые зависимости ставит только задача 01.
- UI строится по `DESIGN.md` (его переписывает задача 02). Язык интерфейса — русский.
- После каждой задачи: `pnpm lint`, `pnpm typecheck`; `pnpm build:ci` — где применимо.
